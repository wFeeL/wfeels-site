# VPS для wfeels.site

Целевая система: Ubuntu 24.04 LTS, 1 CPU, 1 ГБ RAM, 20 ГБ диска, публичный IPv4.
Скрипт не читает `.env`, не принимает пароль и не передаёт SSH-ключи третьим лицам.

## Архитектура

```text
Интернет
  -> VPS :80/:443
  -> Caddy на хосте: TLS и редирект www
  -> 127.0.0.1:8088
  -> Caddy в Docker: статика, /api, лимит тела, 404 и заголовки
  -> api:8000 во внутренней Docker-сети
```

Внешний Caddy отвечает только за публичную границу и сертификаты. Внутренний Caddy
остаётся частью приложения: его конфигурация уже покрыта поведением сайта и не
публикуется наружу — Compose привязывает его только к `127.0.0.1:8088`.

## 1. Передача скрипта

На Mac, из каталога `site-v3/deploy`:

```bash
scp -i ~/.ssh/id_rsa bootstrap-vps.sh root@SERVER_IP:/root/
ssh -i ~/.ssh/id_rsa root@SERVER_IP
chmod 700 /root/bootstrap-vps.sh
/root/bootstrap-vps.sh prepare
```

`prepare` не повторяет полный `apt upgrade`, не отключает текущий root-доступ и не
запускает публичный Caddy. Он выполняет обратимые подготовительные действия.

## 2. Проверка нового пользователя и укрепление SSH

Не закрывая первую root-сессию, открыть второй терминал на Mac:

```bash
ssh -i ~/.ssh/id_rsa deploy@SERVER_IP
sudo true
```

Только если обе команды успешны, в первой root-сессии выполнить:

```bash
/root/bootstrap-vps.sh lockdown
```

Скрипт попросит ввести `LOCKDOWN`, проверит итоговую конфигурацию через `sshd -t` и
`sshd -T`, затем сделает `reload`, не обрывающий открытую сессию.

## 3. Приложение, DNS и HTTPS

Приложение должно отвечать только на `127.0.0.1:8088`. До включения внешнего Caddy:

```bash
curl -i -H 'Host: wfeels.site' http://127.0.0.1:8088/
curl -i -H 'Host: wfeels.site' http://127.0.0.1:8088/api/health
```

После замены обеих DNS-записей `A` (`wfeels.site` и `www.wfeels.site`) на IPv4 VPS:

```bash
sudo /root/bootstrap-vps.sh activate
sudo /root/bootstrap-vps.sh verify
```

`activate` не запускает Caddy, пока одновременно не выполнены три условия: отвечает
сайт, отвечает API и обе DNS-записи уже разрешаются в IPv4 этого VPS. После этого
Caddy получает сертификаты автоматически.

## Установка зависимостей и сборка на VPS

После переноса проекта запустить скрипт обычным пользователем `deploy`, без `sudo`:

```bash
cd /home/deploy/wfeels-site
chmod 700 deploy/setup-project-deps.sh
./deploy/setup-project-deps.sh
```

Он устанавливает Node.js 24 LTS из официального архива с проверкой SHA-256,
инструменты для сборки и зависимости из `web/package-lock.json`. Python на хост
не устанавливается отдельным окружением: API собирается из `api/Dockerfile`.
Chromium для Playwright по умолчанию пропускается; для полного e2e-стенда:

```bash
./deploy/setup-project-deps.sh --with-e2e
```

После установки скрипт печатает команды production-сборки с измерением времени и
пикового расхода RAM, проверки бюджета и запуска Docker Compose.

## Что изменяет prepare

- создаёт `deploy`, копирует ему уже установленный публичный SSH-ключ и выдаёт sudo;
- открывает в UFW только фактический SSH-порт, 80 и 443;
- включает Fail2ban: пять ошибок за десять минут, блокировка на час;
- устанавливает Docker Engine и Compose из подписанного официального APT-репозитория;
- ограничивает стандартные Docker-логи 10 МБ × 3;
- устанавливает Caddy из подписанного официального APT-репозитория;
- включает ежедневные обновления безопасности без автоматической перезагрузки;
- создаёт swap 1 ГБ с `vm.swappiness=10`, если swap ещё отсутствует;
- добавляет локальный MOTD со статусом RAM, swap, диска, Docker и Caddy.

Все пользовательские значения сайта остаются в `deploy/.env`. Скрипт его не читает
и не переносит.
