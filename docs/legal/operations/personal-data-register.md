последующей полной Telegram-доставки. Фактическая работа на VPS проверяется
после публикации; неподанное отдельное трансграничное уведомление отмечено как
остаточный юридический риск.

| `message` | понимание задачи | нет | да | нет |

| `website` | honeypot | нет | нет | факт срабатывания без содержимого |
| `consent` | контроль отправки | нет | нет | версия и результат проверки |
| `consent_version`, `privacy_version` | доказательство редакций | нет | нет | да |
| IP | rate limit и безопасность | нет | нет | не более 1 часа в памяти; в диагностике маскировать |

Telegram получает полную копию заявки только после фиксации основной записи в
РФ. В сообщение включается случайный ID заявки, а не ссылка или токен доступа к
базе. Копия удаляется ботом через 23 часа, а таймер самого закрытого чата
auto-delete — через один день; статус и `message_id`
сохраняются отдельно без дублирования текста.

## 6. Удаление

- ежедневная задача выявляет заявки старше срока;
- перед удалением проверяется отсутствие договора, претензии или законного
  основания продолжить хранение;
- запись удаляется из основной базы;
- составляется акт об уничтожении, а при автоматизированной обработке — также
  выгрузка из журнала информационной системы по приказу Роскомнадзора № 179;
  подтверждения хранятся три года;
- в рабочем журнале остаётся только минимальная отметка, не позволяющая
  восстановить уничтоженные данные;
- локальные резервные копии на российском VPS удаляются не позднее семи дней;
  внешняя услуга резервного копирования RUVDS не подключена;
- Telegram-копия удаляется ботом через 23 часа и таймером чата через один день; при сбое
  удаления событие повторяется и фиксируется без текста заявки;
- временные пароли, токены, ключи и резервные коды отзываются/удаляются сразу
  после передачи или прекращения необходимого доступа и не ждут срока досье;
- договорные данные удаляются после окончания срока, установленного для
  конкретного документа и основания, а не по единому сроку для всей категории.
