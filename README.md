# wfeels — сайт-портфолио v3

Astro 7 (статика) + маленький FastAPI для формы заявки и демо-чата.
Спека: `FREELANCE_LAUNCH/70-workshop/specs/site-v3/`.

## Запуск

    cd web && npm install && npm run dev      # http://localhost:4321
    cd api && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
    cd api && .venv/bin/uvicorn app.main:app --port 8000

## Проверки

    cd web && npm run build && npm run test:unit && npm run test:e2e
    cd web && npm run check:budget
    cd api && .venv/bin/pytest

`check:budget` (`scripts/check-budget.mjs`) читает уже собранный `web/dist` и меряет
вес трёх текстовых страниц: `/`, `/kontakt`, `/politika`. Пределы — 400 КБ на первую
загрузку страницы и 30 КБ сжатого JS. При превышении команда завершается ненулевым
кодом.

Считается то, что браузер реально скачает: HTML, подключённые из разметки CSS и JS,
плюс шрифты, на которые ссылается CSS, — на них нет ссылок в HTML, и обход только по
разметке потерял бы около 148 КБ, больше трети бюджета. Из подмножеств шрифта
считаются кириллица и латиница; `greek`, `cyrillic-ext`, `latin-ext` и `vietnamese`
разделены по `unicode-range` и не грузятся, пока их символы не встретятся в тексте, —
их учёт завысил бы вес. Видео не учитывается: на текстовых страницах его нет.

Превышение бюджета — находка, а не повод поднять предел: на сайте есть утверждение о
весе страницы, и при перевесе снимать надо утверждение, а не проверку.

## Деплой

Разворачивается двумя контейнерами: `api` (образ из `api/Dockerfile`, uvicorn на
внутреннем 8000, запуск не от root) и `caddy` (`caddy:2-alpine` на 80/443).

Caddy отдаёт собранную статику `web/dist` сам и проксирует **только** `/api`.
Упавший API не роняет сайт: перестаёт работать форма, а она деградирует в прямую
ссылку на Telegram. Предел размера тела запроса (64 КБ) стоит на Caddy, до
приложения: приложение читает тело в память целиком до валидации.

Страница 404 отдаётся через `handle_errors`, а не последним кандидатом в
`try_files`, — иначе несуществующий адрес вернулся бы с кодом 200 и поисковик
проиндексировал бы его как дубль. `root` объявлен на уровне сайта: обработчику
ошибок тоже нужно, чем отдавать страницу. Отказ на `/api/*` («форма не
отправилась») идёт своей веткой обработчика — с сохранением кода (502, 413) и с
телом, в котором есть дорога назад к форме. Служебная витрина `/dev/*` закрыта
на Caddy: она собирается вместе с сайтом, но наружу ей не надо.

Контейнер API изолирован: код принадлежит root и процессу приложения только на
чтение, файловая система смонтирована `read_only` (пишется только `tmpfs /tmp`),
capability сброшены, повышение привилегий запрещено. Логи обоих контейнеров
ротируются (`json-file`, 10 МБ × 3): пока Telegram не настроен, заявка целиком
уходит в лог, а он не должен расти без предела.

    cd deploy && cp .env.example .env      # заполнить SITE_DOMAIN, SITE_URL, токен бота
    cd ../web && SITE_URL=https://<домен> npm run build
    cd ../deploy && docker compose config  # синтаксис
    docker compose up -d
    docker compose down

Статика собирается перед подъёмом: `web/dist` монтируется в Caddy только на
чтение, сборка внутрь контейнера не входит. Пересобрали сайт — контейнер
перезапускать не нужно.

Проверка стенда (для локального домена сертификат самоподписанный, отсюда `-k`;
`--resolve` заменяет запись в hosts):

    curl -sk --resolve <домен>:443:127.0.0.1 https://<домен>/api/health   # {"status":"ok"}
    curl -skI --resolve <домен>:443:127.0.0.1 https://<домен>/            # 200
    curl -skI --resolve <домен>:443:127.0.0.1 https://<домен>/net-takoy   # 404, не 200

Секреты только в `deploy/.env` — он в `.gitignore`. В git лежит
`deploy/.env.example` с пустыми значениями.
